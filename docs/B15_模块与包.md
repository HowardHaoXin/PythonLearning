# B15 模块与包

> 模块（一个 `.py` 文件）让代码「可复用」，包（一个含 `__init__.py` 的文件夹）让模块「可组织」，是项目从单文件走向工程化的关键。

## 1. 模块

### 1.1 什么是模块

在 Python 中，**一个 `.py` 文件就是一个模块**。把常用功能写进模块，就能在别处导入复用。

### 1.2 模块的分类

| 分类 | 说明 | 示例 |
| --- | --- | --- |
| 内置模块 | Python 自带，直接 `import` 即可 | `os`、`math`、`random` |
| 第三方模块 | 需 `pip install` 下载后使用 | `requests`、`numpy` |
| 自定义模块 | 自己写的 `.py` 文件，按项目需求封装 | 自己项目的工具函数 |

自定义模块命名注意事项：

1. 命名需符合变量命名规则（不能数字开头、不能用关键字）。
2. 不能与内置模块、第三方模块重名，否则会冲突导致功能失效。

### 1.3 导入与使用（三种方式）

| 方式 | 写法 | 使用 |
| --- | --- | --- |
| 导入整个模块 | `import 模块名 (as 别名)` | `模块名.功能` |
| 导入特定功能 | `from 模块名 import 功能` | 直接用 `功能` |
| 导入全部 | `from 模块名 import *` | 直接用功能名 |

> `import *` 会导入模块里所有内容，容易造成命名污染，一般不建议；要控制范围可用 `__all__`。

### 1.4 小技巧：`if __name__ == "__main__"`

在模块里写测试代码时，直接运行模块能跑测试；但一旦被 `import`，测试代码也会跟着执行。用 `if __name__ == "__main__":` 包住测试代码即可解决：

```python
def add(a, b):
    return a + b

if __name__ == "__main__":   # 只有直接运行本文件时才执行
    print(add(1, 2))         # 测试代码
```

原理：`__name__` 是内置变量，**直接运行**该文件时为 `"__main__"`，**被 import 导入**时为模块名。这个判断因此能区分「直接运行」和「被导入」。

### 1.5 导入模块的注意事项

1. 导入语句写在文件开头，便于阅读组织。
2. 模块只需导入一次（重复导入不会重新执行）。
3. 避免命名冲突。

## 2. 包

### 2.1 什么是包

包是**包含多个相关模块的文件夹**，用来把功能相近的模块组织在一起。

### 2.2 核心标志：`__init__.py`

一个文件夹要被识别为包，需包含 `__init__.py`（Python 3.3+ 可省略，但建议保留）。它的三个作用：

1. **标识目录为包**：告诉 Python「这是包，不是普通文件夹」。
2. **控制导入范围**：用 `__all__` 指定 `from 包 import *` 时要导入的模块。
3. **执行初始化**：导入包时会自动执行该文件的代码（如初始化变量、导入必要模块）。

### 2.3 包的创建

1. 创建文件夹并命名；
2. 在文件夹内创建 `__init__.py`；
3. 创建其他模块文件。

```
mypackage/
├── __init__.py
├── module_a.py
└── module_b.py
```

### 2.4 包的导入与使用（三种方式）

| 方式 | 写法 | 使用 |
| --- | --- | --- |
| 精准导入 | `import 包名.模块名` | `包名.模块名.功能名` |
| 简化导入 | `from 包名 import 模块名` | `模块名.功能名` |
| 批量导入 | `from 包名 import *` | 需在 `__init__.py` 配置 `__all__` |

### 2.5 `__all__` 的使用

`__all__` 是一个列表，专门控制 `from ... import *` 的导入范围：

- 写在 `__init__.py` 里：指定 `from 包名 import *` 要导入的模块。
- 写在模块里：指定 `from 模块名 import *` 要导入的类/函数/变量。

```python
# __init__.py
__all__ = ["module_a", "module_b"]   # 只允许 import * 导入这两个模块
```

### 2.6 导入包的注意事项

1. 包名/模块名不能冲突。
2. `__init__.py` 不要写复杂代码（核心作用是标识包和控制导入）。
3. 导入语句写在开头。
4. 层级不要太深（包嵌套尽量不超过三层）。

## 3. 易错点

- 导入方式不同，调用方式也不同：`import 模块名` 用 `模块名.功能`；`from 模块名 import 功能` 直接用 `功能`。
- 自定义模块名**不要**和内置/第三方模块重名（如不要命名 `random.py`）。
- `from 模块 import *` 会污染命名空间，尽量少用；要控制用 `__all__`。
- 包必须含 `__init__.py`（或明确用命名空间包），否则普通文件夹无法被 `import`。
