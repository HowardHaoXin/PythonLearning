# B14 异常处理

> 异常是程序运行过程中出现的错误。用 `try-except` 捕获异常，能让程序在出错时「不崩溃」并给出友好提示，是提升程序健壮性的关键。

## 1. 什么是异常

- 异常就是程序**运行过程中**出现的错误（区别于语法错误，语法错误在运行前就会被解析器发现）。
- 在 Python 中，异常是**类**，所有异常都继承自 `BaseException`，其中大多数「可被捕获」的异常继承自 `Exception`。

## 2. 常见异常类型

| 异常类 | 说明 |
| --- | --- |
| `NameError` | 变量名错误：使用了未定义的变量名 |
| `SyntaxError` | 语法错误：代码不符合 Python 语法规范 |
| `IndexError` | 索引错误：访问了不存在的索引 |
| `ZeroDivisionError` | 除数为 0 的错误 |
| `KeyError` | 字典中访问了不存在的键 |
| `OSError` | 输入输出错误：文件不存在或无法访问 |
| `AttributeError` | 对象没有该属性或方法 |
| `ValueError` | 值错误：传入了不合法的参数值 |
| `TypeError` | 类型错误：传入了不合法的参数类型 |
| `ImportError` | 导入模块错误：模块不存在或无法导入 |
| `IndentationError` | 缩进错误：代码缩进不符合规范 |

> 补充：`IndentationError` 是 `SyntaxError` 的子类；`IOError` 在 Python 3 中是 `OSError` 的别名。

## 3. 异常处理的两种方式

### 3.1 方式一：traceback 打印异常信息（治本）

用 `traceback` 模块打印详细的异常堆栈，便于定位问题后**返回去修改代码**。

```python
import traceback

try:
    ...
except Exception:
    traceback.print_exc()
```

### 3.2 方式二：try-except 捕获异常（治标）

对于无法避免的异常（如用户输入错误），用 `try-except` 兜底，避免程序崩溃。

```python
try:
    可能发生异常的代码块
except 异常类型1 as 变量名:
    异常处理代码块1
except 异常类型2 as 变量名:
    异常处理代码块2
else:
    没有异常发生时执行的代码块
finally:
    无论是否发生异常都会执行的代码块
```

## 4. 常用捕获写法

### 4.1 捕获所有异常（酌情使用）

```python
try:
    num = int(input("请输入一个整数："))
except Exception:          # Exception 是所有异常的基类，捕获所有非语法异常
    print("输入错误！请输入一个整数~")
```

> 尽量不用：会掩盖未知错误，不利于排查。

### 4.2 捕获指定异常（推荐）

分类型捕获，或一次捕获多个：

```python
try:
    num = int(input("请输入一个整数："))
except (ValueError, NameError):   # 用元组一次捕获多个异常
    print("输入错误！格式不正确或变量名未定义~")
except TypeError:                 # 再单独捕获另一种
    print("输入错误！类型不匹配~")
```

### 4.3 捕获并获取异常信息 `as e`

```python
try:
    num = int(input("请输入一个整数："))
except ValueError as e:           # 用 as 拿到异常对象
    print("输入错误！格式不正确~")
    print(f"异常信息：{e}")        # 打印具体原因，便于定位问题
```

### 4.4 `else` 和 `finally`

- `else`：**没有**异常时才执行，把「成功逻辑」与「异常处理」分开。
- `finally`：**无论是否异常都执行**，常用于释放资源（关闭文件、断开连接等）。

```python
try:
    num = int(input("请输入一个整数："))
except ValueError as e:
    print(f"异常信息：{e}")
else:
    print(f"你输入的整数为：{num}")
finally:
    print("无论是否发生异常，都会执行的代码块~")
```

## 5. 异常处理核心原则

1. **优先捕获具体异常**：不要用 `Exception` 捕获所有异常，会掩盖未知错误。
2. **不滥用异常处理**：语法错误要提前修正，无法靠异常处理解决。
3. **提示要友好**：给用户清晰的提示信息，避免程序崩溃。
4. **`finally` 用于清理**：释放资源、保证程序健壮性，如关闭文件、断开网络连接。

## 6. 抛出自定义异常

除了内置异常，也可以**自己创建并抛出异常**，用来应对业务里的特殊错误（如「余额不足」「账户被冻结」）。

### 6.1 自定义异常的两个步骤

1. **创建异常对象**：`异常类型("具体描述信息")`

   ```python
   e = Exception("余额不足！")
   ```

2. **用 `raise` 抛出异常对象**

   ```python
   raise e
   ```

### 6.2 示例：模拟银行取款

```python
def withdraw(withdraw_amount, account):
    if account["is_frozen"]:                 # 账户被冻结
        raise Exception("账户已冻结！")
    if withdraw_amount > account["balance"]:  # 取款金额大于余额
        raise Exception("余额不足")
    account["balance"] -= withdraw_amount     # 正常取款，扣减余额
    print(f"当前余额{account['balance']}")
```

## 7. 易错点

- 捕获的异常类型要和实际可能抛出的异常**对得上**，否则 `except` 不会命中。
- `except Exception` 过宽，应优先捕获具体异常。
- `else` 和 `finally` 不是必须的，只写 `try` + `except` 也可以。
- 多个 `except` 分支**从上到下**依次匹配，命中一个后其余不再执行，具体异常应写在前面。
- `raise` 会**立即中断**当前函数，抛出异常后后面的代码不再执行（除非上层用 `try-except` 捕获）。
- 字典取值/改值用 `account["balance"]`，**不能用** `account.balance`（字典没有这种属性，会报 `AttributeError`）。
